# SNMP Agent and Notification Receivers

The SNMP Agent support publishes Cacti's own state, such as its **Devices**,
**Data Collectors**, installed **Plugins** and poller statistics, as SNMP
objects, and sends SNMP notifications to the receivers you define when
selected events occur. It allows another management system to monitor the
Cacti installation itself.

## Enabling SNMP Agent Support

SNMP Agent support is controlled by the **SNMP Agent Support Enabled** check
box in the **SNMP Behavior** section of
`Console > Configuration > Settings > Poller`, see
[Poller Settings](Settings-Poller.md). It is enabled by default. The setting
is described in Cacti as: "If this option is checked, Cacti will populate SNMP
Agent tables with Cacti device and system information. It does not enable the
SNMP Agent itself."

When the option is enabled:

- the main **Data Collector** rebuilds the SNMP Agent cache at the end of a
  poller run if the cache is empty, and updates the device and statistics
  objects at the end of every poller run
- the **SNMP Agent Utilities** section appears under
  `Console > Utilities > System Utilities`

When the option is disabled, the SNMP Agent cache is emptied at the end of the
next poller run and the utilities are hidden.

Sending notifications additionally requires the **snmptrap Binary Path** in
`Console > Configuration > Settings > Paths`, see
[Paths Settings](Settings-Paths.md), because Cacti runs that program for
every notification it sends.

## What the SNMP Agent Exposes

The objects are defined by three MIB files in the `mibs` directory of the
Cacti installation. The Cacti enterprise number is 23925.

###### Table 1. MIB files shipped with Cacti

| MIB file | Content |
| --- | --- |
| `CACTI-MIB` | Application data, statistics and the event notifications of Cacti itself |
| `CACTI-SNMPAGENT-MIB` | The test notification `snmpagentNotificationTest`, which can be used to verify the configuration of SNMP managers |
| `CACTI-BOOST-MIB` | Settings and statistics of Boost, see [Boost](Boost.md) |

The `CACTI-MIB` contains the following groups of objects.

###### Table 2. Object groups of the CACTI-MIB

| Group | Objects |
| --- | --- |
| `cactiAppl` | The Cacti, SNMP and RRDtool versions, the poller and Spine settings, and the tables `cactiApplDeviceTable` (description, hostname, status, event count, fail date, recovery date and last error of each **Device**), `cactiApplPollerTable` and `cactiApplPluginTable` (name, status and version of each **Plugin**) |
| `cactiStats` | The totals of **Devices**, **Data Sources** and **Graphs**, the number of **Devices** per status, the re-cache statistics, and the tables `cactiStatsDeviceTable` (minimum, maximum, current and average time, total and failed polls and availability of each **Device**) and `cactiStatsPollerTable` (run time, method, processes, threads, hosts, items, RRDs processed and utilization) |
| `cactiEvents` | The event notifications listed below |

**Plugins** can install their own MIBs into the cache.

The values are stored in the Cacti database. The script
`snmpagent_persist.php` in the Cacti base directory answers `get` and
`getnext` requests for these objects on its standard input and output. When it
starts, it launches `snmpagent_mibcache.php`, which refreshes a copy of the
cache in `cache/mibcache/` every 30 seconds when the cache has changed.

## Notifications

Cacti itself generates the following notifications of the `CACTI-MIB`. The
device notifications are generated at the end of a poller run, by comparing
the new state of each **Device** with the state held in the SNMP Agent cache.

###### Table 3. Notifications generated by Cacti

| Notification | Sent when | Severity |
| --- | --- | --- |
| `cactiNotifyDeviceDown` | A **Device** that was up is now down | High |
| `cactiNotifyDeviceRecovering` | A **Device** that was down is now recovering | Medium |
| `cactiNotifyDeviceFailedPoll` | The failed poll count of a **Device** has increased | Medium |
| `cactiNotifyPollerRuntimeExceeding` | The poller exits because it exceeded its maximum runtime | High |

The device notifications carry the id, description, hostname and last error
of the **Device**. The poller notification carries the index, hostname and IP
address of the poller. The `CACTI-MIB` also defines the generic notification
`cactiNotify`, which only carries a description and can be used by
**Plugins**.

A notification is only sent to the enabled receivers that have this
notification enabled. When no enabled receiver is configured for an event,
Cacti writes a notice to the [Cacti log](Cacti-Log.md) instead.

## SNMP Notification Receivers

The receivers are maintained under
`Console > Utilities > System Utilities > SNMP Notification Receivers`. The
page requires the **Settings/Utilities** permission.

The list shows the **Description**, **Id**, **Status**, **Hostname** and the
number of **Notifications** and **Logs** of each receiver. The actions
`Delete`, `Enable` and `Disable` apply to the selected receivers. Use the add
icon in the title bar to create a receiver.

A receiver has three tabs.

### General

###### Table 4. SNMP Notification Receiver settings

| Setting | Description | Default |
| --- | --- | --- |
| **Description** | Give this SNMP entity a meaningful description. | Empty |
| **Hostname** | Fully qualified hostname or IP address for this device. | Empty |
| **Disable SNMP Notification Receiver** | Check this box if you temporarily do not want to send SNMP notifications to this host. | Off |
| **Maximum Log Size** | The number of days, from 1 to 31, that notification log entries for this receiver are kept. Older entries are removed at the end of a poller run. | `31` |
| **SNMP Message Type** | `NOTIFICATIONS` or `INFORMS`. SNMP traps are always unacknowledged. To send out acknowledged SNMP notifications, formally called "INFORMS", SNMPv2 or above will be required. | `NOTIFICATIONS` |
| **Notes** | Enter notes to this host. | Empty |

The **SNMP Options** section holds the SNMP version, community, port and, for
SNMP version 3, the user name, passwords, protocols and engine id used to
reach the receiver. These are the same fields that are used for a **Device**.

### Notifications

This tab lists every notification known to the SNMP Agent cache with its
**Name**, **OID**, **MIB**, **Kind**, **Max-Access** and whether it is
**Monitored**, which means enabled for this receiver. The list can be
filtered by **MIB**. Select notifications and use the actions `Enable` or
`Disable` to start or stop forwarding them to this receiver. A new receiver
does not receive any notification until at least one is enabled here.

### Logs

This tab lists the notifications that were sent to this receiver with their
**Time**, **Notification** and **Varbinds**. The list can be filtered by
**Severity**, and the `Purge` button removes all log entries of this receiver.

## SNMP Agent Utilities

The other entries of the **SNMP Agent Utilities** section are:

- **View SNMP Agent Cache** - Shows all objects being handled by the SNMP
  Agent with their **OID**, **Name**, **MIB**, **Type**, **Max-Access** and
  **Value**.
- **Rebuild SNMP Agent Cache** - Clears and re-generates the cache from the
  MIB files. It takes another poller run to restore the cache completely.
- **View SNMP Agent Notification Log** - Shows the notifications sent to all
  receivers. The list can be filtered by **Severity** and **Receiver**, and
  `Purge` removes all entries.

## Limits

- The objects are updated by the main **Data Collector** only. The local
  polling statistics do not cover distributed environments.
- Cacti only fills the cache and answers requests through
  `snmpagent_persist.php`. Making the objects reachable over the network
  requires an SNMP daemon that is configured outside of Cacti.
